# Сравнение и план переноса


# Сравнение: скилл `write-enf-story` ↔ шаблон `fiction-arc`

Опорные факты, на которых стоит весь разбор (проверены по коду, не по описаниям):

| Свойство движка ai-story-builder | Значение | Где смотрел |
|---|---|---|
| Типы узлов | `text`, `split`, `merge`, `fix-problems`, `for-each` (+`-input`/`-output`/`-prev-outputs`/`-index`), `lore` | `src/shared/plan-node-types.ts`, `node-edge-dictionary.ts` |
| Типы рёбер | `text`, `textArray` — и всё | там же |
| Исполнение | **строго последовательное**: топологическая очередь, `await` на каждом узле | `src/backend/plan/nodes/generate/regenerateTreeNodesContents.ts:309+` |
| Циклы | обратных рёбер нет; единственный встроенный цикл — внутри `fix-problems` (`maxIterations` × `minSeverityToFix`) | `fix-problems-processor.ts`, `src/shared/fix-problems-plan-node.ts` |
| Логика в промптах | Handlebars: `eq/ne/contains/startsWith/endsWith/or/and/not/matches` + `add/subtract/multiply/divide/ceil/floor/round/min/max` | `src/backend/ai/replaceTemplates.ts:41-95` |
| `lore` | зарегистрирован, но **passthrough-заглушка**; инжекта в промпт нет | `.claude/research/lore.md` |
| Внешние данные / скрипты / файлы | нет ни одного узла с побочным эффектом. Узел = текст на входе → текст на выходе | по списку типов |
| Человек в процессе | визард (один раз, до графа) + статусы `MANUAL`/`in_review` на узле | `plan-graph.md` |

И фактическая начинка цикла чанка в шаблоне (важно: часть того, что «есть только в скилле», там уже есть):

```
Чанк · Номер чанка · Предыдущие чанки → Сборка предыдущих чанков
План чанка → Подробности сцены → Режиссёрские пометки → Проза чанка
→ Расширение прозы (целевой коридор 1450–1550 слов, канву менять нельзя)
→ fix-problems «структура и continuity» → fix-problems «голос и стиль» → Выход
```

## 1. Что есть в скилле и нет в шаблоне

### 1.1 Ложится на существующие узлы (движок трогать не надо)

| Что | Зачем | Как ложится |
|---|---|---|
| **Партитура напряжения** (вес 1–5, ведущий вектор, сопротивление, «придержать») | У шаблона мера сцены одна — `chunk_count ∈ {1,2}`, то есть **длина**. Сила и длина — разные величины; при их отождествлении все сцены выходят одинаковой интенсивности | Один `text` после плана; рёбра в «План чанка» и «Проза чанка». Вектор стыда → в общем шаблоне «источник напряжения» |
| **Поле «придержать»** | Механизма, запрещающего писателю раскрыть что-то в этой сцене, в шаблоне нет вообще. Модель по умолчанию закрывает всё, что открыла | Строка партитуры → в промпт прозы → класс проблемы в `fix-problems` |
| **Ворота библии Б1–Б5** | В шаблоне мир/сеттинг/тему/стиль не проверяет **ни один** узел; ревью есть только у профиля персонажа и у плана. Это ровно та дыра, которую скилл закрыл после прогона, нашедшего 14 блокеров в двух файлах | `merge` библии → 5 find-only `text` → `merge` отчётов → один `text`-правщик. Downstream читает правленую версию |
| **Б2 «посчитать центральный предмет числом»** (масса, парусность, ветер, высота) | Утверждение о физике либо сходится, либо нет; LLM без явного требования посчитать — не считает | Чистый текст в промпте find-инструкций |
| **Б3 «несущие реквизиты сплошным списком»** (где объявлен / откуда взялся / у кого / куда девается) | Проверка по бросающемуся в глаза пропускает то, на чём стоит сюжет | `text`-узел-реестр + пункт в воротах |
| **Ведущие мотивы (2–4) и стоп-лист израсходованных формул** | В шаблоне повтор образа между чанками ловится только тем, что писатель видит все предыдущие чанки целиком, — то есть не ловится | Мотивы: `text` до цикла, ребро в прозу. Стоп-лист — см. 1.2, нужен второй канал |
| **Разделённый конверт писателя** (без будущих сцен, без «горизонта» дальше двух строк) | В шаблоне «План чанка» и «Подробности сцены» видят **полный** «План сцен»; сама проза его не видит, но утечка происходит на шаг выше. Скилл режет по входу, шаблон — запретом в промпте | Переписать рёбра. Ноль движка |
| **Дробление ревью по роду внимания** (связка = 3–6 однородных проверок, один вход) | «Ревью плана сцен: качество» — 14 разнородных классов в одном вызове | N `text`-искателей → `merge` → один правщик |
| **Сведение с дедупликацией и рангом** («ломает ворота истории» ≫ «фактура») | При пяти искателях находок под сорок с сильным перекрытием; в одном списке важное тонет | Отдельный `text` между merge отчётов и правщиком |
| **Читатель** (свежий, без доступа к замыслу, 7 вопросов про эффект, а не про рубрику) | Шаблон рубричен целиком. Рубрика систематически предпочитает гладкий безопасный текст рискованному живому — она видит соблюдение критериев, а не эффект | `text`-узел, у которого **единственный** вход — `merge` прозы. Свежесть в графе конструктивна |
| **Редактор** (единственный, кто режет и переставляет) | Диагноз Читателя без исполнителя — просто текст | `text` над (отчёт Читателя + план + драфт) → инструкции второму циклу переписывания |
| **Полировка по одному правилу за проход** (R1–R8, H1–H6) | Агент с четырнадцатью правилами внимательно делает первые несколько | Цепочка `fix-problems` внутри цикла. Ложится, но +6…14 вызовов на чанк |
| **Правило «не повторять форму соседнего сильного узла»** | Каждый писатель принимает локально разумное решение, и все принимают одно и то же | Промпт + вход «предыдущие чанки». Строго — нужен второй канал (1.2) |
| **Эталоны стиля от пользователя, дословно** | Эталон, сочинённый моделью, фиксирует её текущий потолок, а не поднимает его. Шаблон не спрашивает вовсе | Поле визарда + условный блок в «Стиль» |
| **Табу пользователя** | Отдельного входа нет; всё через синопсис | Поле визарда |
| **Правила однородности длины плана** («ровно N, 50–70 слов, последние не короче первых») | В шаблоне это уже применено к плану сюжета (по заметкам — обязательно, иначе модель истончает хвост), но не к остальным перечислениям | Текст промпта |

### 1.2 Требует нового типа узла или изменения движка

| Что | Почему не ложится |
|---|---|
| **Детерминированные проверки**: `tension_curve.py` (форма кривой), `smoke_part.py` (пустой файл, цех, чужой язык, объём), `repetition_check.py` (n-граммы), `continuity_grep.py`, `wordcount.py` | Узел не умеет выполнять код. Часть имитируется промптом, но «посчитать 4-граммы по 30 000 слов» LLM не делает — делает вид. Нужен **validator/script-узел**: текст на входе, отчёт на выходе, детерминированно. Счётчики слов у узлов, судя по списку неоповещаемых полей, уже считаются — то есть половина данных для порога длины в базе лежит |
| **Карточки состояния `after-NN`** (снимок инвентаря, дуги, «к чему привыкла») | У `for-each` один выход. Состояние, которое не является прозой, некуда положить: либо запихивать в тот же выход и потом резать, либо не переносить. Нужен **второй канал** между итерациями (несколько `for-each-output`, или именованные каналы) |
| **Окно «части старше N−2 не давать»** | `for-each-prev-outputs` отдаёт **все** предыдущие. Нужен параметр окна (последние k) |
| **Стоп по блокеру** («живой блокер останавливает фазу, отчёт пользователю») | В графе узел либо сгенерировал, либо `ERROR`. Состояния «сгенерировал, но дальше нельзя» нет |
| **Перезапуск только задетых связок после правки** | Это обратное ребро. Граф ациклический |
| **Режимы (короткий/средний/длинный) — переменное число проверок** | Число узлов фиксировано шаблоном. Handlebars меняет текст промпта, но не состав графа. Обходится ценой пустых вызовов («если вес < 2 — верни "пропущено"») |
| **Разведка в сети, чтение внешних `rules/`, lore, character sheets** | Нет узла с внешним входом; `lore` — заглушка. Нужен file-input и/или настоящая инжекция lore |
| **Два варианта части и выбор Редактором** | В `graph-primitives-gaps.md` помечено как не поддержанное («Best-of-N / branching»). **Но** сегодня выразимо тремя узлами: A, B и `text`-выбиратель с требованием вывести победителя дословно. Риск: выбиратель перепишет вместо копирования. Проверить на практике, прежде чем закладывать |

## 2. Что есть в шаблоне и нет в скилле

| Что | Стоит ли переносить в скилл | Почему |
|---|---|---|
| **Сцена ≠ чанк.** План в сценах, исполнение в ровно `chunksCount` технических чанках; режимы `full` / `packed` / `fragment`, у `fragment` асимметричные метаданные и `Closing beat` / `Resume after` символ-в-символ на стыке | **Да, в первую очередь** | У скилла часть = сцена = файл, и число частей выбирает планировщик. Прямое следствие — известная беда: части 4 и 6 вышли на 591 и 473 слова при заказанных 1350–1450. Развязка «сколько сцен» от «сколько вызовов» — это ровно то, чего скиллу не хватает |
| **Узел «Расширение прозы»**: второй проход по своей же сцене с целевым коридором 1450–1550 слов и запретом менять канву, первую фразу, последнюю фразу и заголовок | **Да** | Скилл добирает объём переписыванием части целиком (лимит 2 перезапуска) и прямо запрещает добирать описанием. Отдельный проход «наполни уже произошедшее» — другой и более дешёвый механизм. Заодно закрывает открытый вопрос №3 |
| **`expectedPartsCount` → `minItems`/`maxItems` в JSON-схеме + строка в системном промпте** | **Да, как принцип** | «Что можно посчитать — считать, а не просить». В скилле число частей держится на дисциплине |
| **Анкета персонажа генерируется как схема полей под жанр**, а не берётся готовой | Скорее да | Скилл держит фиксированный список полей `07`. Для ENF это осознанно, но правило «поля выводятся из жанра/мира/темы» дешёвое |
| **Арифметика согласования возрастов** («родителю ≥ 16 + возраст ребёнка», «неизвестно» в обязательном поле запрещено) | Да, одна строка | У скилла — «возрасты согласовать между собой» без механизма |
| **Защита от профилирования не того персонажа**: вход подан последней секцией, имя берётся только оттуда | Да | Прямо применимо к person-воротам скилла, которые запускаются по одному на имя |
| **Голоса проектируются всему касту сразу, с правилом «сошлись к одному маркеру — переделать один»** и бюджетом слов | Частично | У скилла есть «неотличимы — это дыра», но нет процедуры разведения |
| **Запрет «это классификация, а не текст произведения» во всех библейных узлах** | Да, дёшево | Защита от протечки прозы в библию; у скилла такого правила нет |
| **Числовая severity 0–100 с порогом `minSeverityToFix` и авто-остановкой цикла** | Как идея — да | У скилла бинарное «блокер / замечание» плюс ручные «лимиты кругов ≈2». Числовой порог тюнится, словесный — нет |
| **Handlebars-арифметика в промпте** (`{{max 3 (ceil (divide chunksCount 2))}}`) | Нет | В скилле эту роль играют Python-скрипты, и играют лучше |
| **`## Часть N` как навигационный примитив** | Нет | У скилла части — отдельные файлы, навигация по имени |
| **Кнопка «Спросить совет» по числу частей** | Нет | У скилла это вопрос пользователю в фазе 0 |

## 3. Где делают одно и то же по-разному

| Задача | Шаблон | Скилл | Чей способ лучше и почему |
|---|---|---|---|
| **Найти и починить** | `fix-problems`: один искатель, он же правщик, цикл по severity | Много узких искателей → сведение с дедупликацией и рангом → **один** правщик | **Скилл по механизму, шаблон по остановке.** У `fix-problems` находка и правка в одной голове, дедупликации между родами внимания нет вовсе (искатель один), а каждая итерация перекатывает текст заново. Зато у него есть числовой порог и автоматический выход из цикла, чего у скилла нет — там «лимит кругов ≈2» на честном слове оркестратора. Правильная сборка — искатели шаблонного стиля (severity в JSON), сведение скилловского стиля, один правщик |
| **Дробить ли ревью** | 14 классов в одном вызове | 3–6 однородных на связку, каждая своим агентом | Скилл — но с оговоркой о цене. Утверждение «три коротких списка дают втрое больше находок» я **не проверял**, это заявление скилла. В скилле дробление бесплатно по календарю (связки идут параллельно), **в графе — нет**: планировщик строго последовательный, и 12 связок это 12 последовательных вызовов. Механизм внимания переносится, экономия времени — не переносится |
| **Память между частями** | Все предыдущие чанки целиком, во все узлы цикла (осознанный выбор «cost-relaxed») | Карточки-снимки состояния + мотивы + индекс; писателю — две последние части дословно | **Не уверен.** Шаблон честнее по фактам: первоисточник, а не пересказ. Скилл дешевле и устойчивее к разбавлению внимания. Но скилл сам пишет, что «пересказ — это место, где пайплайн копирует сам себя», а карточка и есть структурированный пересказ; он выводит себя из-под собственного правила без доказательства. При 20 частях по 1500 слов вход шаблона — ~30k слов, это ещё влезает; при 40 частях уже нет. Правдоподобный гибрид — карточки состояния плюс две последние части дословно, но я бы это измерил, а не постановил |
| **Что видит писатель** | Проза видит план своего чанка, но «План чанка» и «Подробности сцены» видят полный план; утечка будущего запрещена текстом промпта | Режется по входу: полного плана, пунктов N+1 и частей старше N−2 писатель не получает физически | Скилл. Запрет в промпте на входе, который в промпте лежит, — слабее отсутствия входа. Но разница меньше, чем кажется: сама проза в шаблоне полного плана не видит |
| **Длина** | Единица бюджета — вызов; коридор 1450–1550 слов задаётся отдельным проходом расширения | Целевое число слов на часть, `smoke` ловит дикие отклонения | Шаблон. Просить у модели число слов не работает (591 против 1350 — измеренный факт скилла); резать план по числу вызовов и добирать вторым проходом работает |
| **Сила сцены** | `chunk_count ∈ {1,2}` — то есть длина | вес 1–5 + вектор + сопротивление + проверка формы кривой скриптом | Скилл. У шаблона просто нет измерения интенсивности |
| **Проверка формата** | JSON-схема, `minItems`/`maxItems`, детерминированно | Агент читает и говорит «формат сбит» (связка A1) | Шаблон |
| **«Работает ли текст»** | Не спрашивается нигде | Читатель + Редактор, разведённые роли; чистые ворота не отменяют диагноза | Скилл. Это ровно диагноз, который скилл поставил своей же первой версии: система контроля качества без понятия о качестве |
| **Стиль** | Узел «Стиль» выводится из темы и жанра | Эталоны пользователя дословно; не дал — раздела нет и арбитром он не работает | Скилл, при условии что пользователь действительно даёт отрывки. Если не даёт — оба сваливаются в «средний по модели» тон, и скилл это хотя бы помечает |
| **Разделение фактов и голоса при полировке** | Два `fix-problems`: «структура и continuity», затем «голос и стиль» | Ворота C (факты) → ворота D (голос), с явным обоснованием порядка | Здесь они согласны, просто разной гранулярности. Шаблон уже реализует главный порядок скилла |

## 4. План переноса в ai-story-builder

**Первая очередь — ложится на существующие узлы, эффект наибольший:**

1. **Партитура напряжения** отдельным `text`-узлом + рёбра в «План чанка» и «Проза чанка». Без неё все прочие правки косметические: у шаблона нет меры силы сцены.
2. **«Придержать»** — поле партитуры, строка в промпте прозы, класс проблемы в `fix-problems` «структура и continuity».
3. **Ворота библии** (Б1 противоречия · Б2 физика · Б3 полнота под заявку · Б5 мотив и восприятие): `merge` библии → 4–5 find-only `text` → `merge` отчётов → ранжирующий `text` → правщик. Это закрывает самую большую дыру шаблона.
4. **Разбить «Ревью плана сцен: качество»** (14 классов) на 3 связки по роду внимания и собрать через сведение к одному правщику.
5. **Разделённый конверт**: вынести полный «План сцен» из «Подробностей сцены»; оставить план текущего чанка плюс двухстрочный горизонт.
6. **Ведущие мотивы** (2–4 на текст) отдельным узлом до цикла.
7. **Поля визарда**: табу; эталоны стиля (два чужих отрывка) с условным блоком в «Стиль».
8. **Правило «не повторять форму соседней сильной сцены»** в промпт прозы, опираясь на вес из партитуры.

**Вторая очередь — ложится, но дорого по вызовам или требует аккуратной топологии:**

9. **Читатель** по собранному драфту (вход — только `merge` прозы, ничего из замысла) → **Редактор** → второй цикл переписывания по номерам чанков.
10. **Полировка по одному правилу**: цепочка `fix-problems` H1…H6 внутри цикла (+6 вызовов на чанк).
11. **Аудит непрерывности** после сборки: 4 find-only узла по корпусу → отчёт → правка **не корпуса целиком, а по чанкам во втором цикле** (см. п. 5.3).
12. **Два варианта чанка + узел выбора** — сначала проверить, не переписывает ли выбиратель победителя.

**Третья очередь — требует движка:**

13. Окно у `for-each-prev-outputs` (последние k выходов).
14. Второй канал состояния между итерациями → карточки, стоп-лист формул, «предыдущий сильный узел».
15. Validator-узел (детерминированный: число слов и коридор, форма кривой по партитуре, повторяющиеся n-граммы).
16. Условное исполнение узлов — режимы.

**От чего отказаться:**

- Вся ENF-специфика: битва за одежду, уровни и исходы сопротивления, палитра шагов, инвентарь одежды/рук/уз, карта раскрытия. В общий шаблон это не идёт; при желании — отдельный жанровый шаблон.
- Файловая раскладка целиком: `bible/`, `cards/`, `reviews/`, `parts/`, `_index`, `tail_dirty`, `closed(N)`, resume. Её роль в графе играют узлы, статусы и `OUTDATED`-каскад. Переносить нечего.
- `plan-changelog.md`, `dirty-spans.md` — журналы ручного процесса.
- Буквальное «одна связка — один агент»: в графе связка это узел, агентов нет.
- Правила про `subagent_type`, `capability_mode: read-only`, компактизацию контекста — целиком про агентское исполнение (см. 5).
- «Лимит кругов ≈2, дальше стоп и отчёт пользователю» — у `fix-problems` уже есть `maxIterations`; человеческий стоп делает пользователь кнопкой.

## 5. Чего перенести нельзя

**5.1 Свежесть агента и «отдельный подагент на связку» — это как раз переносится, и лучше, чем в скилле.**
Стоит сказать прямо, потому что вопрос предполагает обратное. Каждый узел — отдельный stateless-вызов ровно с теми входами, которые вписаны рёбрами. Болезнь, ради которой скилл завёл `enf-planner` («оркестратор держит в контексте всю написанную им библию и потому не называет того, что помнит сам»), в графе конструктивно невозможна: узел «План сцен» физически не видит ничего, кроме своих входов. Скилл тратит на это отдельный агент, `promptMode: full`, отключение наследования скиллов и раздел про компактизацию — граф получает то же даром. Соответственно и весь раздел скилла про типы подагентов и компактизацию переносить не нужно: он лечит болезнь, которой у графа нет.

**5.2 Параллельность — не переносится, но и не является свойством скилла как метода.**
Планировщик графа последовательный: `while (queue.length) { ... await context.onNodeStart(...) }`. Инвариант «Find параллельно, Fix по одному» в графе вырождается: параллели нет, а «один правщик на один текст» выполняется автоматически — у каждого узла ровно один автор. Практическое следствие одно и оно неприятное: **дробление ворот, которое в скилле бесплатно по календарю, в графе стоит линейного времени.** Прежде чем дробить одно ревью на пять, стоит убедиться, что находок действительно втрое больше — этого измерения я не видел ни у одной стороны.

**5.3 Что не переносится по существу:**

| Свойство | Почему в графе так не выйдет |
|---|---|
| **Обратные рёбра**: «перезапустить задетые связки», «Редактор возвращает закрытую часть в работу», «пока повторный поиск не чист — фаза 8 не начинается» | Граф ациклический. Единственный цикл — внутри `fix-problems`, и он один узел / один искатель / один порог. Всё остальное разворачивается в конечное число проходов вперёд, зафиксированное автором шаблона заранее |
| **Шлагбаум по блокеру** | Нет состояния «сгенерировал, но дальше нельзя». Ближайшее — `in_review`/`MANUAL`, то есть ручной просмотр человеком, а не автоматическая остановка |
| **Правка корпуса целиком** (фазы 6–8: сквозное чтение → структурная правка → полировка по всему тексту) | Читать целое можно (128k вход), **писать целое нельзя**: выходной лимит вызова ~1500 слов — на этом стоит вся арифметика шаблона. Любая корпусная правка обязана быть «прочитать целое → чинить по кускам во втором цикле». Это не потеря качества, но это другая топология, и её надо проектировать, а не переносить |
| **Инструменты**: разведка в сети, чтение внешних `rules/`, character sheets, lore | Узел — чистая функция текста в текст. `lore` — заглушка |
| **Детерминированные проверки** (пять .py-скриптов) | Ноль эквивалентов. Промптом имитируется только то, что не требует счёта |
| **Второй канал состояния между итерациями** (карточки, мотивы, «предыдущий сильный узел») | У `for-each` один выход |
| **Человек в середине**: «остановиться ли после плана», выбор варианта, эталоны стиля | Визард спрашивает один раз, до графа. Дальше человек может только смотреть узлы и жать регенерацию |
| **Динамическая форма проверок**: режимы, «P1/P2 только при весе ≥ 2», «person на каждое имя из чеклиста» | Число узлов фиксировано шаблоном; переменной может быть только длина `textArray`. «Ревью на каждого персонажа» ложится (`for-each` по касту), «ворота процесса только при весе ≥ 2» — нет, только как пустой вызов с ответом «пропущено» |

## 3. Чего в CLI нет и чем заменить

1. **JSON Schema.** У grok есть (`--json-schema`, проверено). У claude нет — единственный честный путь: схема в системный промпт + `stringFormat: false`, то есть уже существующая в интерфейсе ветка (`ai-engine-adapter.ts:39-46`). Адаптер должен сам форсить `stringFormat=false`, а не полагаться на вызывающего.
2. **Токены и телеметрия.** Есть на строке `result` / в `--output-format json`. Маппинг в `ResponseUsage`:
   ```
   input_tokens                     ← usage.input_tokens
   input_tokens_details.cached_tokens ← usage.cache_read_input_tokens
   output_tokens                    ← usage.output_tokens
   output_tokens_details.reasoning_tokens ← usage.reasoning_tokens (только --output-format json)
   cost_in_usd_ticks                ← total_cost_usd_ticks  ИЛИ  Math.round(total_cost_usd * 1e10)
   ```
   Тогда `extractProviderCostUsd` и `recordCall` работают без правок. Отдельно записывать в `error_message`/лог, что ~6.3 К input-токенов — оверхед хостинга CLI, иначе агрегатор `scripts/aggregate-telemetry.ts` будет врать про стоимость шаблона.
3. **Отмена.** `AbortSignal` → убийство **дерева** процессов. `child.kill()` на Windows не убьёт внуков (`claude.cmd` → `node`), нужен `taskkill /pid <pid> /T /F`; на POSIX — `detached:true` + `process.kill(-pid,'SIGTERM')`, через 3 с `SIGKILL`. Мягкая отмена (как closing SSE) отсутствует: токены за уже сгенерированное всё равно оплачены, но `result` не придёт → usage будет `null`, телеметрия запишет success=false.
4. **Параллельные вызовы.** У HTTP-адаптера параллельность бесплатна; здесь каждый вызов — процесс на 150–300 МБ и +6.3 К токенов. Нужен семафор на движок (`max_parallel`, по умолчанию 2) и `--no-leader` у grok, чтобы вызовы не дрались за общий leader-сокет `~/.grok/leader.sock`. Одинаковый `--session-id` в двух параллельных процессах = ошибка («must not already exist»).
5. **Таймауты.** У CLI их нет. Свой: `timeout_ms` (дефолт 10 мин, как `timeout: 5*60*1000` в `grok-client.ts:15`, но CLI медленнее), плюс «стоп по тишине» — если > N минут нет ни одной NDJSON-строки, считать процесс зависшим и убивать.
6. **Retry / коды ошибок.** HTTP-статуса нет, есть только exit code + stderr. Классифицировать по хвосту stderr (auth / rate limit / not found) и прокидывать через `makeErrorWithStatus` (`src/backend/lib/make-errors.ts`).

## 4. Грабли

**Длина командной строки.** Windows `CreateProcess` — 32 767 символов на всю строку, `cmd.exe` — 8 191. Промпт в 38 КБ в argv = гарантированный `ENAMETOOLONG`/обрезка. Отсюда жёсткое правило: пользовательский промпт **всегда** идёт через `--prompt-file`/stdin; системный промпт длиной > 8 000 — тоже в файл (у grok можно попробовать `--agent <definition-file>`, но это непроверено — дефолт должен быть «блок `<<<SYSTEM>>>` в prompt-файле»). Никакого `shell: true` и никакой ручной экранизации кавычек: `spawn(bin, args, {shell:false})`.

**`.cmd`-шимы.** `grok.exe` — настоящий exe, всё хорошо. `claude` на Windows обычно ставится npm-шимом `claude.cmd`, а Node ≥18.20/20.12 запрещает `spawn` `.cmd` без shell. Решение в `run-cli.ts`: если путь оканчивается на `.cmd`/`.bat`, запускать `process.env.ComSpec` с `["/d","/s","/c", `"${bin}"`, ...args]` и `windowsVerbatimArguments: true` — и тогда снова упираться в лимит 8 191, что ещё раз обязывает держать argv коротким.

**Кодировка.** stdout читать как байты и декодировать `new StringDecoder("utf8")` (чанки рвут UTF-8 посередине символа — кириллица посыплется). Prompt-файл писать `fs.writeFileSync(p, text, "utf8")` — без BOM; PowerShell `Out-File` тут использовать нельзя. Строки резать по `/\r?\n/`. В env выставить `NO_COLOR=1`, `FORCE_COLOR=0`, `TERM=dumb`, `CI=1`, иначе в `plain`-режиме прилетают ANSI-escape-последовательности спиннера.

**Рабочий каталог.** Смертельная граблина: CLI подхватывает контекст каталога. `--cwd D:/repos/ai-story-builder` затянет `CLAUDE.md` проекта, `.claude/`, `.mcp.json` (в репе есть!), скиллы и плагины прямо в системный промпт — то есть модель будет писать роман, зная правила коммитов. Запускать **только** в пустом scratch-каталоге: `path.join(app.getPath("userData"), "cli-scratch", engineId, callId)`, создавать перед запуском и удалять после. Для claude дополнительно `--strict-mcp-config --mcp-config "{}"`.

**Состояние сессий.** Каждый вызов пишет транскрипт: grok — в `~/.grok/sessions`, claude — в `~/.claude/projects/<slug-от-cwd>`. Это (а) неограниченный рост диска, (б) текст романа пользователя утекает в домашний каталог за пределы проекта. Меры: никаких `--resume`/`--continue`; `--session-id` — новый UUID на вызов; `--no-memory` у grok (иначе cross-session memory тащит прошлые главы в следующие вызовы и ломает воспроизводимость); периодическая чистка scratch и предупреждение в UI-хинте настройки.

**Прочее по мелочи.** `--tools ""` не работает (проверено — все 26 инструментов остались); отключать только через полный `--disallowed-tools`. `--max-turns 1` обязателен, иначе агент может уйти в многоходовку и вернуть не текст, а отчёт о работе. `--verbatim` у grok — чтобы CLI не переупаковывал промпт. Аутентификация: у grok `apiKeySource: "oauth"` — ключ берётся из `~/.grok`, поля `api_key` в конфиге движка нет вообще, `testConnectivity` должен проверять не ключ, а наличие бинаря и успешный `--version`.

### `src/backend/ai/cli/run-cli.ts`

```ts
import { type ChildProcess, spawn } from "node:child_process"
import { StringDecoder } from "node:string_decoder"

export interface RunCliSpec {
  bin: string
  args: string[]
  cwd: string
  stdin?: string
  timeoutMs: number
  /** Kill if no stdout line arrives for this long. 0 disables. */
  idleTimeoutMs: number
  abortSignal: AbortSignal
  onLine: (line: string) => void
}

export interface RunCliResult {
  code: number | null
  stderrTail: string
  killedBy: "abort" | "timeout" | "idle" | null
}

function killTree(child: ChildProcess): void {
  if (child.pid == null) return
  if (process.platform === "win32") {
    // child.kill() leaves grandchildren (claude.cmd -> node) alive.
    spawn("taskkill", ["/pid", String(child.pid), "/T", "/F"], { stdio: "ignore" }).unref()
  } else {
    try { process.kill(-child.pid, "SIGTERM") } catch { /* already gone */ }
    setTimeout(() => { try { process.kill(-child.pid!, "SIGKILL") } catch {} }, 3000).unref()
  }
}

export function runCli(spec: RunCliSpec): Promise<RunCliResult> {
  return new Promise((resolve, reject) => {
    const isShim = /\.(cmd|bat)$/i.test(spec.bin)
    const bin = isShim ? (process.env.ComSpec ?? "cmd.exe") : spec.bin
    const args = isShim ? ["/d", "/s", "/c", `"${spec.bin}"`, ...spec.args] : spec.args

    const child = spawn(bin, args, {
      cwd: spec.cwd,
      windowsHide: true,
      windowsVerbatimArguments: isShim,
      detached: process.platform !== "win32", // own process group → killable as a tree
      stdio: ["pipe", "pipe", "pipe"],
      env: {
        ...process.env,
        NO_COLOR: "1", FORCE_COLOR: "0", TERM: "dumb", CI: "1",
        DISABLE_AUTOUPDATER: "1", DISABLE_TELEMETRY: "1",
        CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC: "1",
      },
    })

    let killedBy: RunCliResult["killedBy"] = null
    const decoder = new StringDecoder("utf8") // chunk boundaries split UTF-8 — never toString()
    let buf = ""
    let stderrTail = ""
    let lastLineAt = Date.now()

    const hardTimer = spec.timeoutMs > 0
      ? setTimeout(() => { killedBy = "timeout"; killTree(child) }, spec.timeoutMs)
      : null
    const idleTimer = spec.idleTimeoutMs > 0
      ? setInterval(() => {
          if (Date.now() - lastLineAt > spec.idleTimeoutMs) { killedBy = "idle"; killTree(child) }
        }, 5000)
      : null

    const onAbort = () => { killedBy = "abort"; killTree(child) }
    spec.abortSignal.addEventListener("abort", onAbort, { once: true })

    child.stdout.on("data", (chunk: Buffer) => {
      buf += decoder.write(chunk)
      let nl: number
      // CRLF on Windows.
      while ((nl = buf.search(/\r?\n/)) >= 0) {
        const line = buf.slice(0, nl)
        buf = buf.slice(nl + (buf[nl] === "\r" ? 2 : 1))
        lastLineAt = Date.now()
        if (line.trim()) spec.onLine(line)
      }
    })
    child.stderr.on("data", (chunk: Buffer) => {
      stderrTail = (stderrTail + chunk.toString("utf8")).slice(-4000)
    })

    const cleanup = () => {
      if (hardTimer) clearTimeout(hardTimer)
      if (idleTimer) clearInterval(idleTimer)
      spec.abortSignal.removeEventListener("abort", onAbort)
    }

    child.on("error", (e) => { cleanup(); reject(e) })
    child.on("close", (code) => {
      const rest = buf + decoder.end()
      if (rest.trim()) spec.onLine(rest)
      cleanup()
      resolve({ code, stderrTail, killedBy })
    })

    if (spec.stdin != null) {
      child.stdin.end(Buffer.from(spec.stdin, "utf8")) // explicit UTF-8, no BOM
    } else {
      child.stdin.end()
    }
  })
}
```

### `src/backend/ai/cli/cli-event-mapper.ts`

```ts
import type OpenAI from "openai"
import type { ResponseStreamEvent, ResponseUsage } from "openai/resources/responses/responses.js"

type Emit = (e: ResponseStreamEvent) => void

/**
 * Both `grok --output-format streaming-messages-json` and
 * `claude --output-format stream-json` emit NDJSON in the Anthropic Messages
 * wire format. This maps it onto the OpenAI Responses events the app's UI
 * already understands (RegenerationPanel.tsx:40-56, AiThinkingPanel.tsx:33-58).
 */
export class CliEventMapper {
  text = ""
  usage: (Partial<ResponseUsage> & { cost_in_usd_ticks?: number }) | null = null
  isError = false
  errorMessage: string | null = null

  private started = false
  private blockKind = new Map<number, "thinking" | "text">()

  constructor(private readonly emit?: Emit) {}

  push(line: string): void {
    let msg: any
    try { msg = JSON.parse(line) } catch { return } // banner / stray log line
    switch (msg.type) {
      case "system":
        if (msg.subtype === "init" && !this.started) {
          this.started = true
          this.emit?.({ type: "response.created", response: { id: msg.session_id } } as any)
        }
        return
      case "stream_event":
        this.onStreamEvent(msg.event)
        return
      case "result":
        this.onResult(msg)
        return
    }
  }

  private onStreamEvent(e: any): void {
    switch (e?.type) {
      case "content_block_start": {
        const kind = e.content_block?.type === "thinking" ? "thinking" : "text"
        this.blockKind.set(e.index, kind)
        this.emit?.({
          type: "response.output_item.added",
          output_index: e.index,
          item: kind === "thinking"
            ? { id: `r_${e.index}`, type: "reasoning", summary: [] }
            : { id: `m_${e.index}`, type: "message", role: "assistant", status: "in_progress", content: [] },
        } as any)
        return
      }
      case "content_block_delta": {
        if (e.delta?.type === "thinking_delta") {
          this.emit?.({
            type: "response.reasoning_summary_text.delta",
            output_index: e.index, summary_index: 0, delta: e.delta.thinking,
          } as any)
        } else if (e.delta?.type === "text_delta") {
          this.text += e.delta.text
          this.emit?.({
            type: "response.output_text.delta",
            output_index: e.index, content_index: 0, delta: e.delta.text,
          } as any)
        }
        return
      }
      case "content_block_stop": {
        this.emit?.({ type: "response.output_item.done", output_index: e.index,
          item: { id: `m_${e.index}`, type: "message", role: "assistant", status: "completed", content: [] } } as any)
        return
      }
    }
  }

  private onResult(msg: any): void {
    this.isError = !!msg.is_error
    if (this.isError) this.errorMessage = String(msg.result ?? msg.subtype ?? "cli error")
    // `result` carries the final text even when partial deltas were missed.
    if (typeof msg.result === "string" && !this.text) this.text = msg.result

    const u = msg.usage ?? {}
    const ticks =
      typeof msg.total_cost_usd_ticks === "number" ? msg.total_cost_usd_ticks
      : typeof msg.total_cost_usd === "number" ? Math.round(msg.total_cost_usd * 1e10)
      : undefined

    this.usage = {
      input_tokens: u.input_tokens ?? 0,
      output_tokens: u.output_tokens ?? 0,
      total_tokens: (u.input_tokens ?? 0) + (u.output_tokens ?? 0),
      input_tokens_details: { cached_tokens: u.cache_read_input_tokens ?? 0 },
      output_tokens_details: { reasoning_tokens: u.reasoning_tokens ?? 0 },
      // Read by extractProviderCostUsd() with USD_PER_TICK = 1e-10.
      ...(ticks != null ? { cost_in_usd_ticks: ticks } : {}),
    } as any

    this.emit?.({ type: "response.completed", response: { usage: this.usage } } as any)
  }
}
```

### `src/backend/ai/cli-adapter.ts`

```ts
import fs from "node:fs"
import os from "node:os"
import path from "node:path"
import { randomUUID } from "node:crypto"
import type { AiEngineConfig } from "@shared/ai-engine-config.js"
import type OpenAI from "openai"
import type { CliAiGenerationSettings } from "../../shared/cli-ai-generation-settings.js"
import type { AiEngineAdapter, GenerateResponseRequest } from "./ai-engine-adapter.js"
import { isVerboseLogging } from "./ai-logging.js"
import lastAiGenerationEventManager from "./last-ai-generation-event-manager.js"
import { CliEventMapper } from "./cli/cli-event-mapper.js"
import type { CliFlavor } from "./cli/cli-flavor.js"
import { runCli } from "./cli/run-cli.js"
import { Semaphore } from "./cli/cli-semaphore.js"
import { SettingsRepository } from "../settings/settings-repository.js"
import { makeErrorWithStatus } from "../lib/make-errors.js"

export class CliAdapter implements AiEngineAdapter<CliAiGenerationSettings> {
  private readonly gate = new Semaphore(2)

  constructor(private readonly flavor: CliFlavor) {}

  async generateResponse(
    req: GenerateResponseRequest<CliAiGenerationSettings>,
    onEvent?: (event: OpenAI.Responses.ResponseStreamEvent) => void,
  ): Promise<string> {
    const engineConfig =
      req.engineConfig ?? (SettingsRepository.getAllAiEnginesConfig() as any)[this.flavor.id] ?? {}

    const s: CliAiGenerationSettings = {
      ...engineConfig.defaultAiGenerationSettings,
      ...req.aiGenerationSettings,
    }

    const bin = (engineConfig.binary_path as string)?.trim() || this.flavor.defaultBin
    const timeoutMs = Number(s.timeout_ms) > 0 ? Number(s.timeout_ms)
      : Number(engineConfig.timeout_ms) > 0 ? Number(engineConfig.timeout_ms)
      : this.flavor.defaultTimeoutMs
    this.gate.setLimit(Number(engineConfig.max_parallel) > 0 ? Number(engineConfig.max_parallel) : 2)

    // NEVER the project repo: the CLI would inherit CLAUDE.md / .mcp.json / skills
    // from cwd straight into its system prompt.
    const root = (engineConfig.work_dir as string)?.trim() || path.join(os.tmpdir(), "ai-story-builder-cli")
    const scratchDir = path.join(root, this.flavor.id, `${req.promptCacheKeys[0] ?? "call"}-${randomUUID()}`)
    fs.mkdirSync(scratchDir, { recursive: true })

    // The CLI has no JSON-schema mode for every flavor — fall back to the
    // "schema in the system prompt, route parses the text" path the interface
    // already models via `stringFormat: false`.
    const wantsNativeSchema = !!req.responseSchema && req.stringFormat !== false
    let systemPrompt = req.systemPrompt ?? ""
    if (req.responseSchema && !this.flavorSupportsSchema()) {
      systemPrompt +=
        `\n\n## Output format\nReturn ONLY a JSON object matching this JSON Schema, with no prose ` +
        `and no markdown fences:\n${JSON.stringify(req.responseSchema.schema)}`
    }

    const plan = this.flavor.build({
      systemPrompt,
      userPrompt: req.userPrompt ?? "",
      model: s.model,
      reasoningEffort: s.reasoning_effort,
      maxTurns: s.max_turns && s.max_turns > 0 ? s.max_turns : 1,
      webSearch: !!s.web_search,
      responseSchema: this.flavorSupportsSchema() && wantsNativeSchema ? req.responseSchema : undefined,
      scratchDir,
      writeFile: (name, content) => {
        const p = path.join(scratchDir, name)
        fs.writeFileSync(p, content, "utf8") // UTF-8, no BOM — CLI reads it verbatim
        return p
      },
      extraArgs: String(engineConfig.extra_args ?? "").split(/\s+/).filter(Boolean),
    })

    const mapper = new CliEventMapper(onEvent)
    const release = await this.gate.acquire(req.abortSignal)
    try {
      if (isVerboseLogging()) console.log(`[${this.flavor.id}] spawn ${bin} ${plan.args.join(" ")}`)
      const t0 = Date.now()
      const result = await runCli({
        bin,
        args: plan.args,
        cwd: scratchDir,
        stdin: plan.stdin,
        timeoutMs,
        idleTimeoutMs: Math.min(timeoutMs, 5 * 60 * 1000),
        abortSignal: req.abortSignal,
        onLine: (line) => {
          if (isVerboseLogging()) console.log(`[${this.flavor.id}] ${line.slice(0, 400)}`)
          mapper.push(line)
        },
      })
      console.log(`[${this.flavor.id}] exit=${result.code} ${Date.now() - t0}ms chars=${mapper.text.length}`)

      if (result.killedBy === "abort") throw new Error(`${this.flavor.id}: aborted by user`)
      if (result.killedBy) throw new Error(`${this.flavor.id}: killed by ${result.killedBy} after ${timeoutMs}ms`)
      if (result.code !== 0) throw new Error(`${this.flavor.id} exited ${result.code}: ${result.stderrTail.trim()}`)
      if (mapper.isError) throw new Error(`${this.flavor.id}: ${mapper.errorMessage}`)
      if (!mapper.text.trim()) throw new Error(`${this.flavor.id}: empty output. stderr: ${result.stderrTail.trim()}`)

      if (mapper.usage) lastAiGenerationEventManager.onAiGenerationEvent(mapper.usage as any)
      return mapper.text
    } finally {
      release()
      // Session transcripts still land in ~/.grok/sessions or ~/.claude/projects —
      // only the scratch dir is ours to clean.
      fs.rmSync(scratchDir, { recursive: true, force: true })
    }
  }

  async testConnectivity(
    settings: AiEngineConfig<CliAiGenerationSettings>,
  ): Promise<{ ok: boolean; detail?: string; error?: string }> {
    const bin = (settings.binary_path as string)?.trim() || this.flavor.defaultBin
    const dir = fs.mkdtempSync(path.join(os.tmpdir(), "asb-cli-probe-"))
    let out = ""
    try {
      const r = await runCli({
        bin, args: this.flavor.versionArgs, cwd: dir,
        timeoutMs: 30_000, idleTimeoutMs: 0,
        abortSignal: AbortSignal.timeout(30_000),
        onLine: (l) => { out += `${l}\n` },
      })
      if (r.code !== 0) return { ok: false, error: `exit ${r.code}: ${r.stderrTail.trim() || out.trim()}` }
      return { ok: true, detail: `${bin}: ${out.trim() || "ok"}` }
    } catch (e: any) {
      if (e?.code === "ENOENT") throw makeErrorWithStatus(`binary not found: ${bin}`, 400)
      return { ok: false, error: String(e) }
    } finally {
      fs.rmSync(dir, { recursive: true, force: true })
    }
  }

  private flavorSupportsSchema(): boolean {
    return this.flavor.id === "grok-cli"
  }
}
```

```ts
export class Semaphore {
  private queue: Array<() => void> = []
  private inUse = 0
  constructor(private limit: number) {}
  setLimit(n: number) { this.limit = Math.max(1, n); this.drain() }
  async acquire(signal?: AbortSignal): Promise<() => void> {
    if (signal?.aborted) throw new Error("aborted")
    if (this.inUse < this.limit) { this.inUse++; return () => this.release() }
    await new Promise<void>((resolve, reject) => {
      const onAbort = () => { this.queue = this.queue.filter((f) => f !== run); reject(new Error("aborted")) }
      const run = () => { signal?.removeEventListener("abort", onAbort); resolve() }
      this.queue.push(run)
      signal?.addEventListener("abort", onAbort, { once: true })
    })
    this.inUse++
    return () => this.release()
  }
  private release() { this.inUse--; this.drain() }
  private drain() { while (this.inUse < this.limit && this.queue.length) this.queue.shift()!() }
}
```

## 2. `/v1/chat/completions` или `/api/chat` — берём нативный

Соблазн взять OpenAI-совместимый эндпоинт понятен: `createOllamaClient()` в три строки как `yandex-client.ts`. Но:

1. **Responses API у Ollama нет вообще.** `/v1` — это только `chat/completions`, `completions`, `embeddings`, `models`. Оба существующих адаптера строят `ResponseCreateParamsStreaming` и получают `ResponseStreamEvent` — код переиспользовать всё равно не выйдет, события придётся синтезировать вручную в любом случае. Единственная экономия от SDK — парсер SSE, а это ~20 строк.
2. **`options` не пробрасывается через `/v1`.** `num_ctx` задать невозможно — ни телом запроса, ни заголовком. Остаются только `OLLAMA_CONTEXT_LENGTH` в окружении демона или `PARAMETER num_ctx` в Modelfile. Для приложения, где промпт скачет от 2 до 160 КБ (см. §5), управление контекстом из кода — не опция, а требование. **Это решающий аргумент.**
3. **`keep_alive` тоже только в нативном API.** При прогоне дерева из 19 узлов выгрузка модели между вызовами стоит дороже самой генерации.
4. **`think` и стрим размышлений.** Нативный `/api/chat` отдаёт `message.thinking` отдельным полем — это ложится один в один на `response.reasoning_summary_text.delta`, и `AiThinkingPanel` начинает работать бесплатно. В `/v1` рассуждения либо приезжают в нестандартном `reasoning_content`, либо вклеиваются в контент тегами `<think>`.
5. **`format` схемой.** В `/v1` есть `response_format`, но нативный `format` принимает JSON Schema напрямую, без обёртки `json_schema.schema` (§3).
6. **Метрики.** Финальный чанк несёт `prompt_eval_count` / `eval_count` / `*_duration` — этого достаточно и для `ResponseUsage`, и для детекции обрезки промпта.

**Решение: нативный `POST /api/chat`, `stream: true`, NDJSON, голый `fetch` с `makeLoggingFetch`.** OpenAI SDK в этом адаптере не используется — только его *типы* событий на выходе.

### Стриминг и отмена

NDJSON, по строке на токен-чанк:

## 3. Структурированный вывод: `format` ↔ `responseSchema` / `stringFormat`

Маппинг тривиальный — Ollama принимает JSON Schema **как есть**, без обёртки:

```ts
if (req.responseSchema && req.stringFormat !== false) {
  body.format = req.responseSchema.schema   // ровно тот же объект, что уходит в text.format.schema у Grok
  if (body.options.temperature == null) body.options.temperature = 0
}
```

Но есть три отличия от `strict: true` у Grok/Yandex, которые надо учесть в коде:

**(1) `format` — это грамматика, а не валидатор.** Ollama конвертирует схему в GBNF и физически не даёт сэмплеру выйти за неё. Плюс: невалидный JSON вернуть невозможно. Минус: **`description` из схемы в грамматику не попадает**. А в `generate-split-parts.ts:20-23` вся семантика куска сидит именно в `items.description` (`partDescription` из настроек узла). С Grok эта строка едет в API и модель её видит; с Ollama она бы потерялась. Поэтому адаптер **всегда дублирует схему в system-промпт**:

```ts
function buildSchemaInstruction(spec: JsonSchemaSpec): string {
  return [
    `Respond with a single JSON object named "${spec.name}" and nothing else — no prose, no markdown fences.`,
    spec.description ? `Purpose: ${spec.description}` : null,
    "It must validate against this JSON Schema:",
    JSON.stringify(spec.schema),
  ].filter(Boolean).join("\n")
}
```

Дописывается в конец system-сообщения. Это же лечит известную болячку Ollama: с `format` и без словесной инструкции модель иногда упирается в бесконечный пробел перед открывающей скобкой.

**(2) Не все ключевые слова переживают конвертацию.** `minItems`/`maxItems` (нужны в `buildSplitResponseSchema` при заданном `expectedPartsCount`) в GBNF поддерживаются, а вот `$ref`, `oneOf`/`allOf`, сложные `pattern` — частично или никак. Схемы проекта простые (`FOUND_PROBLEMS_JSON_SCHEMA`, splitResult), но если Ollama вернёт `400 invalid format schema`, адаптер должен деградировать, а не падать:

```ts
// в ollama-adapter: одна повторная попытка без грамматики, со схемой только в промпте —
// это ровно то же, что даёт stringFormat:false у облачных движков.
catch (e) {
  if (isFormatRejected(e) && body.format) {
    console.warn("[Ollama] model/schema rejected `format`, retrying with prompt-only schema")
    delete body.format
    return await run(body)
  }
  throw e
}
```

**(3) `stringFormat:false` работает без изменений.** Условие `req.responseSchema && req.stringFormat !== false` копируется дословно из `grok-adapter.ts:73`; при `false` схема уезжает только текстом, а `JSON.parse` делает вызывающая сторона (`generate-split-parts.ts:122`, ретраи `MAX_ATTEMPTS=3` — они здесь особенно полезны, локальные 7–8B модели сваливаются с формата чаще).

> Терминологическая сноска: в задаче поле названо `enforceSchema`, в коде оно `stringFormat` (`ai-engine-adapter.ts:44`). Если имя всё-таки решено чинить — переименование затрагивает три файла: интерфейс, `grok-adapter.ts:73`, `yandex-adapter.ts:65`.

### Где это вылезет: цифры с этой машины

Реальное соотношение по этим данным — **≈ 3 символа на токен** (17299/5809) у токенизатора Grok. У локальных моделей с Llama/Qwen-токенизатором русский текст режется мельче: закладываться надо на **2 символа/токен**. То есть промпт в 38 КБ — это **~19 000 токенов**, а не «влезет в 8k».

### Почему это опаснее, чем кажется

**Ollama при превышении `num_ctx` не возвращает ошибку.** Она молча выкидывает голову промпта (оставляя `num_keep` токенов) и генерирует по хвосту. Дефолт `num_ctx` — **4096** токенов (`OLLAMA_CONTEXT_LENGTH`). Результат: system-промпт с правилами стиля и половина лора исчезают, модель отвечает на огрызок, генерация формально «успешна», телеметрия пишет `success: true`. Это самый дорогой класс багов — тихая деградация качества на 1000+ вызовов.

### Конкретные места в коде

- `generate-plan-node-text-content.ts:23-24` — `replaceTemplates(aiUserPrompt, nodeInputsToReplacements(inputs))` вклеивает **целиком** тексты всех входных узлов. В `fiction-arc.ru.json` у `.plan.nodes[10].children[1]` — **7 входов**, у `.plan.nodes[8]` и `[12]` — по 6. Отсюда и p95 в 80 КБ.
- `generate-fix-problems.ts:37` — цикл итераций, каждая пересылает полный исходник заново.
- `generate-split-parts.ts:104` — `MAX_ATTEMPTS = 3`, полный текст ×3, и при этом **выход** доходит до 14 КБ (~7k токенов): `num_ctx` должен покрывать промпт **плюс** генерацию.
- `generate-summary.ts:60` — `userPrompt = instructions + весь content`; max 131 КБ при медиане 2.3 КБ.

### Что делать — три уровня защиты в адаптере

**(1) Автоподбор `num_ctx` по модели.** `POST /api/show {model}` отдаёт `model_info["<architecture>.context_length"]` (у qwen3 — 40960, у llama3.1 — 131072) и `capabilities`. Кэшируем на процесс. Считаем нужное окно и берём степень двойки:

```ts
const need = estimatedPromptTokens + outputReserve + CTX_SAFETY_SLACK
const numCtx = clamp(nextPowerOfTwo(need), MIN_NUM_CTX, modelMaxCtx)
```

**(2) Preflight-исключение вместо тихой обрезки.** Если `need > numCtx` (пользователь сам задал маленький `num_ctx`) или `need > modelMaxCtx` — бросаем с человеческим текстом, включающим оба числа и подсказку. Это ровно тот же контракт, что `response.incomplete` у Grok (`grok-client.ts:69`) — вызывающий код уже умеет ловить и показывать.

**(3) Пост-проверка по факту.** В финальном чанке `prompt_eval_count` — точное число реально обработанных токенов. Если оно упёрлось в `num_ctx` — промпт обрезали, и это ошибка, а не предупреждение. Плюс `done_reason: "length"` = ответ обрублен по `num_predict`/контексту → тоже throw.

### Что делать вне адаптера

- **VRAM.** `num_ctx: 32768` на 8B-модели — это ~4 ГБ одного только KV-кэша в f16. Рекомендация в `notes`/README: `OLLAMA_FLASH_ATTENTION=1` + `OLLAMA_KV_CACHE_TYPE=q8_0` (режет KV вдвое почти без потери качества).
- **Уровень шаблонов.** Правильное лечение p95 в 80 КБ — не раздувать окно, а не слать полный текст. В проекте уже есть механизм саммари (`generate-summary.ts`, настройка `autoGenerateSummary`), и точка расширения одна: `PlanNodeService.findNodeInputsByType(node.id, "text")` (вызывается в `generate-plan-node-text-content.ts:20`, `generate-split-parts.ts:73`, `generate-fix-problems.ts:31`). Отдельный тип входа `"summary"`, который подставляет `summary` исходного узла вместо `content`, снял бы проблему для всех локальных движков разом. Это отдельная задача, не часть адаптера, но её стоит завести.
- **`num_predict`.** Для split-узлов минимум 8192 (p95 выхода 14 КБ). Это per-node override через `plan_nodes.ai_settings` → `{"ollama": {"num_predict": 8192, "num_ctx": 16384}}` — механизм уже есть (`generate-split-parts.ts:96-100`).

```ts
/**
 * POST /api/show — окно модели и её capabilities.
 * Ответ статичен для пары (baseUrl, model), поэтому кэшируется на процесс:
 * при прогоне дерева адаптер иначе дёргал бы его сотни раз.
 */
export async function ollamaShow(baseUrl: string, apiKey: string | undefined, model: string): Promise<OllamaModelInfo> {
  const cacheKey = `${baseUrl}|${model}`
  const cached = showCache.get(cacheKey)
  if (cached) return cached

  const r = await ollamaFetch(baseUrl, apiKey, "/api/show", { method: "POST", body: JSON.stringify({ model }) })
  if (!r.ok) throw new Error(`Ollama /api/show failed for '${model}': HTTP ${r.status}: ${await r.text()}`)

  const data = (await r.json()) as { model_info?: Record<string, unknown>; capabilities?: string[] }
  const modelInfo = data.model_info ?? {}
  // Ключ зависит от архитектуры: "qwen3.context_length", "llama.context_length", ...
  const ctxEntry = Object.entries(modelInfo).find(([k]) => k.endsWith(".context_length"))
  const contextLength = typeof ctxEntry?.[1] === "number" ? (ctxEntry[1] as number) : null

  const info: OllamaModelInfo = { contextLength, capabilities: data.capabilities ?? [] }
  showCache.set(cacheKey, info)
  return info
}

/**
 * POST /api/chat со stream:true. Отдаёт NDJSON-чанки по мере поступления.
 *
 * Отмена: signal уходит в fetch; reader.cancel() в finally обязателен — без него
 * при досрочном выходе из цикла сокет остаётся открытым и слот раннера занятым.
 */
export async function* ollamaChatStream(
  baseUrl: string,
  apiKey: string | undefined,
  body: OllamaChatRequest,
  signal: AbortSignal,
): AsyncGenerator<OllamaChatChunk> {
  const r = await ollamaFetch(baseUrl, apiKey, "/api/chat", {
    method: "POST",
    body: JSON.stringify(body),
    signal,
  })
  if (!r.ok) throw new Error(`Ollama /api/chat failed: HTTP ${r.status}: ${await r.text()}`)
  if (!r.body) throw new Error("Ollama /api/chat returned an empty body")

  const reader = r.body.getReader()
  const decoder = new TextDecoder()
  let buffer = ""

  try {
    for (;;) {
      const { done, value } = await reader.read()
      if (done) break
      buffer += decoder.decode(value, { stream: true })

      let nl: number
      // biome-ignore lint/suspicious/noAssignInExpressions: канонический разбор NDJSON
      while ((nl = buffer.indexOf("\n")) >= 0) {
        const line = buffer.slice(0, nl).trim()
        buffer = buffer.slice(nl + 1)
        if (!line) continue
        if (isVerboseLogging()) console.log(`[Ollama] chunk ${line.slice(0, 500)}`)
        const chunk = JSON.parse(line) as OllamaChatChunk
        if (chunk.error) throw new Error(`Ollama error: ${chunk.error}`)
        yield chunk
      }
    }
    const tail = buffer.trim()
    if (tail) yield JSON.parse(tail) as OllamaChatChunk
  } finally {
    await reader.cancel().catch(() => {})
  }
}
```

### `src/backend/ai/ollama-adapter.ts`

```ts
import { randomUUID } from "node:crypto"
import type { AiEngineConfig, OllamaEngineConfig } from "@shared/ai-engine-config.js"
import type OpenAI from "openai"
import type { OllamaAiGenerationSettings } from "../../shared/ollama-ai-generation-settings.js"
import { makeErrorWithStatus } from "../lib/make-errors.js"
import { SettingsRepository } from "../settings/settings-repository.js"
import type { AiEngineAdapter, GenerateResponseRequest, JsonSchemaSpec } from "./ai-engine-adapter.js"
import lastAiGenerationEventManager from "./last-ai-generation-event-manager.js"
import {
  type OllamaChatRequest,
  ollamaChatStream,
  ollamaListModels,
  ollamaShow,
  ollamaVersion,
  resolveBaseUrl,
} from "./ollama-client.js"

/**
 * Консервативная оценка «символов на токен» для подбора num_ctx.
 * Телеметрия проекта даёт ~3.0 на токенизаторе Grok (17299 симв / 5809 ток.),
 * но Llama/Qwen дробят кириллицу мельче. Занижаем до 2 — лучше выделить
 * лишнее окно, чем молча потерять голову промпта.
 */
const CHARS_PER_TOKEN = 2
/** Резерв под ответ, когда num_predict не задан. p95 вывода split-узлов ≈ 7k токенов. */
const DEFAULT_OUTPUT_RESERVE = 8192
const CTX_SAFETY_SLACK = 512
const MIN_NUM_CTX = 8192
/** Насколько близко prompt_eval_count может подойти к num_ctx, чтобы не считать это обрезкой. */
const TRUNCATION_MARGIN = 16

export class OllamaAdapter implements AiEngineAdapter<OllamaAiGenerationSettings> {
  async generateResponse(
    req: GenerateResponseRequest<OllamaAiGenerationSettings>,
    onEvent?: (event: OpenAI.Responses.ResponseStreamEvent) => void,
  ): Promise<string> {
    const engineConfig: OllamaEngineConfig =
      (req.engineConfig as OllamaEngineConfig | undefined) ?? SettingsRepository.getAllAiEnginesConfig().ollama ?? {}

    const baseUrl = resolveBaseUrl(engineConfig)
    const apiKey = engineConfig.api_key?.trim() || undefined

    const settings: OllamaAiGenerationSettings = {
      ...engineConfig.defaultAiGenerationSettings,
      ...req.aiGenerationSettings,
    }

    const model = settings.model?.trim()
    if (!model) throw new Error("Ollama model is required (pick one in engine settings)")

    // ── Сообщения ─────────────────────────────────────────────────────────
    // includeExistingLore / engineFileIds сознательно игнорируются:
    // capabilities.fileUpload = false, вложений у локального движка нет.
    const enforceSchema = req.responseSchema != null && req.stringFormat !== false
    const systemParts: string[] = []
    if (req.systemPrompt?.trim()) systemParts.push(req.systemPrompt)
    if (req.responseSchema) {
      // Схему дублируем в промпт ВСЕГДА, даже при включённой грамматике:
      // GBNF не переносит `description` из схемы, а в generate-split-parts
      // именно там лежит partDescription.
      systemParts.push(buildSchemaInstruction(req.responseSchema))
    }
    const systemPrompt = systemParts.join("\n\n")

    const messages: OllamaChatRequest["messages"] = []
    if (systemPrompt) messages.push({ role: "system", content: systemPrompt })
    messages.push({ role: "user", content: req.userPrompt ?? "" })

    // ── Размер контекста ──────────────────────────────────────────────────
    const modelInfo = await ollamaShow(baseUrl, apiKey, model)
    const promptChars = systemPrompt.length + (req.userPrompt?.length ?? 0)
    const estimatedPromptTokens = Math.ceil(promptChars / CHARS_PER_TOKEN)
    const outputReserve = positive(settings.num_predict) ?? DEFAULT_OUTPUT_RESERVE
    const numCtx = resolveNumCtx({
      requested: positive(settings.num_ctx),
      estimatedPromptTokens,
      outputReserve,
      modelMaxCtx: modelInfo.contextLength,
      model,
      promptChars,
    })

    // ── Тело запроса ──────────────────────────────────────────────────────
    const body: OllamaChatRequest = {
      model,
      messages,
      stream: true,
      keep_alive: engineConfig.keep_alive?.trim() || undefined,
      options: {
        num_ctx: numCtx,
        num_predict: positive(settings.num_predict),
        temperature: enforceSchema ? (settings.temperature ?? 0) : positive(settings.temperature, true),
        top_p: positive(settings.top_p, true),
        seed: positive(settings.seed, true),
      },
    }

    // `think` принимают только модели с capability "thinking";
    // остальным Ollama отвечает 400, поэтому параметр молча снимаем.
    if (settings.think && modelInfo.capabilities.includes("thinking")) {
      body.think = settings.think === "none" ? false : settings.think
    }

    if (enforceSchema) body.format = req.responseSchema!.schema

    try {
      return await this.runChat(baseUrl, apiKey, body, req.abortSignal, numCtx, onEvent)
    } catch (e) {
      // Схема может оказаться неконвертируемой в GBNF ($ref, экзотические
      // комбинаторы). Один ретрай без грамматики — схема остаётся в промпте,
      // JSON парсит вызывающая сторона, как при stringFormat:false.
      if (body.format && isFormatRejection(e)) {
        console.warn(`[Ollama] '${model}' rejected \`format\`, retrying with prompt-only schema:`, e)
        const { format: _dropped, ...retry } = body
        return await this.runChat(baseUrl, apiKey, retry as OllamaChatRequest, req.abortSignal, numCtx, onEvent)
      }
      throw e
    }
  }

  /** Прогон одного стрима + синтез ResponseStreamEvent'ов для фронта и телеметрии. */
  private async runChat(
    baseUrl: string,
    apiKey: string | undefined,
    body: OllamaChatRequest,
    abortSignal: AbortSignal,
    numCtx: number,
    onEvent?: (event: OpenAI.Responses.ResponseStreamEvent) => void,
  ): Promise<string> {
    const responseId = `resp_ollama_${randomUUID()}`
    const reasoningItemId = `rs_${randomUUID()}`
    const messageItemId = `msg_${randomUUID()}`

    let sequence = 0
    // Строгие типы Responses-API требуют полей, которых у нас физически нет
    // (logprobs, полный Response). Тот же приём, что `as unknown as Tool`
    // в grok-adapter.ts / yandex-adapter.ts.
    const emit = (event: Record<string, unknown>): void => {
      onEvent?.({ ...event, sequence_number: sequence++ } as unknown as OpenAI.Responses.ResponseStreamEvent)
    }
    const responseShell = (status: string, usage?: unknown) => ({
      id: responseId,
      object: "response",
      created_at: Math.floor(Date.now() / 1000),
      model: body.model,
      status,
      output: [],
      ...(usage ? { usage } : {}),
    })

    let text = ""
    let thinking = ""
    let reasoningOpen = false
    let messageOpen = false
    let outputIndex = 0
    let messageOutputIndex = 0
    let final: { promptTokens: number | null; outputTokens: number | null; doneReason?: string } | null = null

    // RegenerationPanel.tsx:40 ждёт этого события, чтобы переключиться в "Запрос отправлен".
    emit({ type: "response.created", response: responseShell("in_progress") })

    for await (const chunk of ollamaChatStream(baseUrl, apiKey, body, abortSignal)) {
      if (abortSignal.aborted) throw new Error("aborted")

      const thinkingDelta = chunk.message?.thinking
      if (thinkingDelta) {
        if (!reasoningOpen) {
          reasoningOpen = true
          emit({
            type: "response.output_item.added",
            output_index: outputIndex,
            item: { id: reasoningItemId, type: "reasoning", summary: [], status: "in_progress" },
          })
        }
        thinking += thinkingDelta
        // AiThinkingPanel.tsx:42 накапливает это в summary[summary_index].text.
        emit({
          type: "response.reasoning_summary_text.delta",
          delta: thinkingDelta,
          item_id: reasoningItemId,
          output_index: outputIndex,
          summary_index: 0,
        })
      }

      const contentDelta = chunk.message?.content
      if (contentDelta) {
        if (reasoningOpen && !messageOpen) {
          emit({
            type: "response.output_item.done",
            output_index: outputIndex,
            item: {
              id: reasoningItemId,
              type: "reasoning",
              status: "completed",
              summary: [{ type: "summary_text", text: thinking }],
            },
          })
          outputIndex += 1
        }
        if (!messageOpen) {
          messageOpen = true
          messageOutputIndex = outputIndex
          emit({
            type: "response.output_item.added",
            output_index: messageOutputIndex,
            item: { id: messageItemId, type: "message", role: "assistant", status: "in_progress", content: [] },
          })
        }
        text += contentDelta
        emit({
          type: "response.output_text.delta",
          delta: contentDelta,
          content_index: 0,
          item_id: messageItemId,
          output_index: messageOutputIndex,
          logprobs: [],
        })
      }

      if (chunk.done) {
        final = {
          promptTokens: chunk.prompt_eval_count ?? null,
          outputTokens: chunk.eval_count ?? null,
          doneReason: chunk.done_reason,
        }
      }
    }

    if (messageOpen) {
      emit({
        type: "response.output_item.done",
        output_index: messageOutputIndex,
        item: {
          id: messageItemId,
          type: "message",
          role: "assistant",
          status: "completed",
          content: [{ type: "output_text", text, annotations: [] }],
        },
      })
    }

    // ── Пост-проверки ─────────────────────────────────────────────────────
    // Ollama обрезает промпт молча. prompt_eval_count — единственный точный
    // признак того, что голова запроса не доехала до модели.
    if (final?.promptTokens != null && final.promptTokens >= numCtx - TRUNCATION_MARGIN) {
      throw new Error(
        `[Ollama] prompt was truncated: the model processed ${final.promptTokens} tokens with num_ctx=${numCtx}. ` +
          `The beginning of the prompt (system instructions) was silently dropped. ` +
          `Raise "Context window (num_ctx)" for this node/engine or shorten the inputs.`,
      )
    }
    // Аналог response.incomplete у Grok (grok-client.ts:69).
    if (final?.doneReason === "length") {
      throw new Error(
        `[Ollama] response incomplete: generation stopped at the num_predict / context limit ` +
          `(num_ctx=${numCtx}, num_predict=${body.options?.num_predict ?? "unset"}). ` +
          `Produced ${text.length} chars.`,
      )
    }

    const usage = {
      input_tokens: final?.promptTokens ?? 0,
      output_tokens: final?.outputTokens ?? 0,
      total_tokens: (final?.promptTokens ?? 0) + (final?.outputTokens ?? 0),
      input_tokens_details: { cached_tokens: 0 },
      output_tokens_details: { reasoning_tokens: 0 },
    }
    // Стоимости нет: extractProviderCostUsd вернёт null и в ai_call_stats
    // ляжет cost_usd = NULL — штатное поведение, см. telemetry.ts.
    lastAiGenerationEventManager.onAiGenerationEvent(usage)
    emit({ type: "response.completed", response: responseShell("completed", usage) })

    return text
  }

  async testConnectivity(
    settings: AiEngineConfig<OllamaAiGenerationSettings>,
  ): Promise<{ ok: boolean; detail?: string; error?: string }> {
    const config = settings as OllamaEngineConfig
    const baseUrl = resolveBaseUrl(config)
    const apiKey = config.api_key?.trim() || undefined
    try {
      const [version, models] = await Promise.all([
        ollamaVersion(baseUrl, apiKey),
        ollamaListModels(baseUrl, apiKey),
      ])
      if (models.length === 0) {
        return { ok: true, detail: `Connected to Ollama ${version} at ${baseUrl}, but no models are pulled yet.` }
      }
      return { ok: true, detail: `Connected. Ollama ${version} at ${baseUrl}, ${models.length} model(s) available.` }
    } catch (e) {
      // Самая частая ошибка — демон не запущен: ECONNREFUSED без HTTP-статуса.
      const message = e instanceof Error ? e.message : String(e)
      if (/ECONNREFUSED|fetch failed/i.test(message)) {
        return { ok: false, error: `Cannot reach Ollama at ${baseUrl}. Is the daemon running? (${message})` }
      }
      return { ok: false, error: message }
    }
  }
}

function positive(value: unknown, strict = false): number | undefined {
  if (typeof value !== "number" || !Number.isFinite(value)) return undefined
  if (strict) return value >= 0 ? value : undefined
  return value > 0 ? value : undefined
}

/**
 * Текстовая копия схемы для system-промпта. Нужна и при включённой грамматике:
 * GBNF не переносит `description`, а именно там сидят подсказки автора шаблона.
 */
function buildSchemaInstruction(spec: JsonSchemaSpec): string {
  return [
    `Respond with a single JSON object named "${spec.name}" and nothing else — no prose, no markdown fences.`,
    spec.description ? `Purpose: ${spec.description}` : null,
    "The object must validate against this JSON Schema:",
    JSON.stringify(spec.schema),
  ]
    .filter(Boolean)
    .join("\n")
}

function nextPowerOfTwo(n: number): number {
  let p = 1
  while (p < n) p *= 2
  return p
}

/**
 * Подбор num_ctx. Тихая обрезка промпта — самый дорогой отказ у локальных
 * моделей (success:true при потерянном system-промпте), поэтому нехватка окна
 * здесь всегда исключение, а не предупреждение.
 */
function resolveNumCtx(args: {
  requested: number | undefined
  estimatedPromptTokens: number
  outputReserve: number
  modelMaxCtx: number | null
  model: string
  promptChars: number
}): number {
  const { requested, estimatedPromptTokens, outputReserve, modelMaxCtx, model, promptChars } = args
  const need = estimatedPromptTokens + outputReserve + CTX_SAFETY_SLACK
  const kb = (promptChars / 1024).toFixed(1)

  if (requested != null) {
    if (need > requested) {
      throw makeErrorWithStatus(
        `[Ollama] prompt does not fit the configured context window: ${kb} KB ≈ ${estimatedPromptTokens} tokens ` +
          `+ ${outputReserve} reserved for the answer > num_ctx=${requested}. ` +
          `Raise num_ctx (needs ≥ ${need}), lower num_predict, or feed the node shorter inputs.`,
        400,
      )
    }
    return requested
  }

  if (modelMaxCtx != null && need > modelMaxCtx) {
    throw makeErrorWithStatus(
      `[Ollama] prompt does not fit model '${model}': ${kb} KB ≈ ${estimatedPromptTokens} tokens ` +
        `+ ${outputReserve} reserved > model context length ${modelMaxCtx}. ` +
        `Use a longer-context model or shorten the node inputs.`,
      400,
    )
  }

  const auto = Math.max(MIN_NUM_CTX, nextPowerOfTwo(need))
  return modelMaxCtx != null ? Math.min(auto, modelMaxCtx) : auto
}

/** 400 от Ollama на невалидную/неконвертируемую в GBNF схему. */
function isFormatRejection(e: unknown): boolean {
  const message = e instanceof Error ? e.message : String(e)
  return /HTTP 400/.test(message) && /format|schema|grammar/i.test(message)
}
```
